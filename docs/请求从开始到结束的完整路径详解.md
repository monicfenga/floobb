# FlooBB 请求从开始到结束的完整路径详解

> 本文档是 `请求从开始到结束的完整路径.mmd` 的伴侣文件，详细解释 FlooBB 中 HTTP 请求的完整生命周期。
> 格式与《Xiuno BBS 请求从开始到结束的完整路径详解》一致，方便对照阅读。

## 概述

FlooBB 与 Xiuno 的最大区别：**Xiuno 是"单入口 + switch-case 路由文件"，FlooBB 是"单入口 + 类控制器"**。整个流程分为两个主要阶段：

1. **初始化阶段（引导）**：`init.php` 完成常量定义、库加载、自动加载注册、会话与登录恢复
2. **业务逻辑阶段**：`index.php` 通过 `Router::dispatch()` 把请求分发给 `app/` 下的某个控制器的某个方法

没有 MySQL——数据全部由 flatDB（文件存储）读写。

### 请求链路总览（一图流）

```
浏览器 GET /floobb/user/view/Geticer
  │
  ├─ 1. index.php（唯一入口）→ require init.php
  ├─ 2. init.php 引导：常量 / lib 加载 / 自动加载 / session / CSRF token / Auth::resume()
  ├─ 3. index.php：$seg = Router::segments() → ['user','view','Geticer']
  │     Router::dispatch('user')
  │        action = 'view'（第 2 段，缺省 'index'）
  │        args   = ['Geticer']（第 3 段起）
  │        POST 请求且存在 viewPost() → 调 viewPost()，否则调 view()
  ├─ 4. UserController::view('Geticer')：调 Model 层（User/Topic/Post）取数据
  └─ 5. 渲染：header.tpl.php → user_view.tpl.php → footer.tpl.php → exit
```

## 初始化阶段

### 1. 用户发送请求

用户访问 FlooBB 的任意页面，例如：

- 首页：`http://example.com/floobb/`
- 主题详情：`http://example.com/floobb/topic/view/t1`
- 用户资料：`http://example.com/floobb/user/view/Geticer`

**所有请求统一打到一个文件：`index.php`**（单入口前端控制器）。
若 rewrite/PATH_INFO 不可用，回退格式为 `index.php?r=topic/view/t1`。

### 2. index.php 定义安全常量并装载 init.php

**代码位置**：[index.php:3-8](file:///m:/laragon/www/floobb/index.php#L3-L8)

```php
const FLOO = TRUE;
if (file_exists("install.php")) header("Location: install.php");
require_once("init.php");
```

`FLOO` 常量是所有后续文件的"门禁"：每个文件头部都有 `defined('FLOO') or die('potato')`，防止被直接访问。

### 3. init.php 引导

**代码位置**：[init.php](file:///m:/laragon/www/floobb/init.php)

**关键操作**：

| 步骤 | 内容 | 位置 |
|---|---|---|
| 3.1 | 定义常量：`DS`、`PATH_ROOT`、`THEME_DIR`、`UPLOADS_DIR`、`DATA_DIR`、`APP_BASE`（子文件夹部署基准路径）等 | [init.php:16-52](file:///m:/laragon/www/floobb/init.php#L16-L52) |
| 3.2 | DEBUG 模式：错误上报到 `error.log` 并直接显示 | [init.php:57-72](file:///m:/laragon/www/floobb/init.php#L57-L72) |
| 3.3 | 加载 `lib/` 下的库：Flatdb、Router、Utils、CSRF、Auth、Parsedown(+Extra)、Pagination、Captcha、files | [init.php:81-90](file:///m:/laragon/www/floobb/init.php#L81-L90) |
| 3.4 | 注册自动加载 `floo_spl_autoload` | [init.php:99-110](file:///m:/laragon/www/floobb/init.php#L99-L110) |
| 3.5 | `header_register_callback`：响应前输出 `Server-Timing` 头（含 DB 读写计数 + 总耗时） | [init.php:118-125](file:///m:/laragon/www/floobb/init.php#L118-L125) |
| 3.6 | 安装守卫：`config` 库不存在 → 生成 `install.php` 并跳转；已安装则自毁 install.php，读入 `$conf` | [init.php:143-156](file:///m:/laragon/www/floobb/init.php#L143-L156) |
| 3.7 | `session_start()`；CSRF `$token` 只在缺失时生成（POST 校验的是上一页渲染的 token）；`Auth::resume()` 恢复登录态（含 RememberMe） | [init.php:158-162](file:///m:/laragon/www/floobb/init.php#L158-L162) |
| 3.8 | 准备全局 `$header`（页面标题/关键词/描述） | [init.php:167-173](file:///m:/laragon/www/floobb/init.php#L167-L173) |

**自动加载规则（重要）**——全项目禁 namespace，按类名后缀分流：

```php
// init.php:99-108
function floo_spl_autoload($class) {
    if (substr($class, -10) === 'Controller') {
        // UserController → app/user.controller.php
        $file = PATH_ROOT . DS . 'app' . DS . strtolower(substr($class, 0, -10)) . '.controller.php';
    } else {
        // User / Topic → model/User.php / model/Topic.php
        $file = PATH_ROOT . DS . 'model' . DS . $class . '.php';
    }
    is_file($file) and require_once $file;
}
```

这意味着控制器和 Model **不需要任何 include 语句**，第一次 `new UserController()` 或 `User::get()` 时自动加载。

### 4. 数据存储（对比 Xiuno 的"数据库连接"）

FlooBB 没有 db_connect。数据层是 `lib/Flatdb.lib.php`（flatDB）：每个"表"对应 `data/` 下的一组文件，由各 Model 类封装读写。全局变量 `$FLATDB_TOTAL_QUERY_NUM` 记录本次请求的 C/R/U/D 操作数，最终体现在 `Server-Timing` 响应头里。

## 业务逻辑阶段

### 5. 回到 index.php：解析 URL

**代码位置**：[index.php:16-18](file:///m:/laragon/www/floobb/index.php#L16-L18)

```php
$seg = Router::segments();
$controller = isset($seg[0]) ? strtolower((string) $seg[0]) : 'home';
if (!preg_match('/^[a-z][a-z0-9_]*$/', $controller)) $controller = 'home';
```

`Router::segments()` 的解析优先级（[Router.lib.php:145-168](file:///m:/laragon/www/floobb/lib/Router.lib.php#L145-L168)）：

1. `$_SERVER['PATH_INFO']`（如 `/user/view/Geticer`）
2. `$_GET['r']`（回退，如 `?r=user/view/Geticer`）
3. 都没有 → 空数组（首页）

解析后返回**有序段数组**，并把段并入 `$_REQUEST`——所以 `param(0)`、`param(1)` 这套 Xiuno 风格的取参函数在这里仍然可用（`param(0)='user'`，`param(1)='view'`，`param(2)='Geticer'`）。

### 6. 路由分发（三位置契约）

**代码位置**：[index.php:20](file:///m:/laragon/www/floobb/index.php#L20) + [Router.lib.php:202-226](file:///m:/laragon/www/floobb/lib/Router.lib.php#L202-L226)

```php
Router::dispatch('user');
```

`dispatch()` 内部逻辑：

1. `$action = $seg[1] ?? 'index'`（第 2 段，缺省 index），只允许 `[A-Za-z_][A-Za-z0-9_]*`，防路径注入
2. `$args = array_slice($seg, 2)`（第 3 段起作为方法参数）
3. 拼类名：`ucfirst('user') . 'Controller'` → `UserController`（触发自动加载 app/user.controller.php）
4. **HTTP 方法感知**：POST 请求且存在 `actionPost()` 方法（如 `settingsPost()`）→ 优先调它；否则调 `action()`
5. 找不到类或方法 → 返回 false，index.php 输出 404 页

### 7. URL 与代码的对应关系（三位置契约）

```
/{控制器}/{动作}/{参数…}      →  {Controller}::{action}({参数…})

/                             → HomeController::index()
/forum/view/f1                → ForumController::view('f1')
/topic/view/t1                → TopicController::view('t1')
/topic/create/f1     GET      → TopicController::create('f1')   （渲染表单）
/topic/create/f1     POST     → TopicController::createPost('f1')（处理提交）
/user/view/Geticer            → UserController::view('Geticer')
/user/settings       GET      → UserController::settings()
/user/settings       POST     → UserController::settingsPost()
/auth/login          POST     → AuthController::loginPost()
```

**page/sort/filter 等修饰符不进路径**，一律走 query string：`/forum/view/f1?page=2&sort=oldest`，控制器里用 `Router::query('page')` / `Router::query('sort')` 读取。

### 8. 控制器内的前置判断

与 Xiuno 相同的思想，但落在控制器方法开头：

```php
// app/user.controller.php:77-80（settingsPost）
if (!Auth::csrfCheck()) self::forbidden();   // CSRF 校验，失败 403
$user = Auth::user();
if ($user === null) self::redirect('auth/login');  // 未登录跳转

// app/user.controller.php:21-30（view）
$user = User::get($name);
if ($user === null) { http_response_code(404); /* 渲染 404 页 */ }
```

### 9. Model 层数据处理

控制器调用 `model/` 下 4 个仓储类（全部静态方法，无实例化）：

**model/User.php**（用户）
```php
User::get($username)            // 读单个用户（含 password_hash、bio、avatar…）
User::exists($username)         // 用户名是否存在
User::create(array $data)       // 创建用户（含 recovery_codes 生成）
User::save($username, $data)    // 保存用户
User::validName/validPassword/validEmail/validNickname/validBio   // 校验器
User::generateRecoveryCodes / consumeRecoveryCode                 // 恢复码
```

**model/Topic.php**（主题）
```php
Topic::get($tid) / create() / save() / delete()
Topic::listByForum($fid, $sort)         // 版块主题列表（latest/oldest）
Topic::listLatest($limit)               // 全站最新（首页用）
Topic::countByAuthor / listByAuthor     // 用户主页"近期发帖"用
Topic::incrViews($tid)                  // 浏览 +1
Topic::isLocked / isSticky / canEdit    // 状态与权限判断
```

**model/Post.php**（回帖）
```php
Post::get($pid) / listByTopic($tid) / create() / save() / delete()
Post::countByAuthor / listByAuthor
Post::render($markdown)                 // Parsedown 渲染 Markdown 正文
```

**model/Forum.php**（版块）
```php
Forum::get($fid) / exists() / listAll() / create() / save()
Forum::lastActive($fid)                 // 版块最后活跃（首页列表用）
Forum::adjustCounts($fid, $topicsDelta, $postsDelta)  // 主题/回帖计数增减（发帖、删帖、移题时）
Forum::setStickyRef($fid, $tid, $on)    // 维护 forums.sticky_topic_ids（置顶）
```

与 Xiuno 不同：**没有缓存层、没有 `xxx_format()` 这类格式化函数**，转义统一发生在模板输出时（`htmlspecialchars`）。

### 10. 视图渲染（两种风格并存）

**风格 A：私有 `render()` 辅助方法**（大多数控制器动作使用）

```php
// app/user.controller.php:153-166
private static function render($tpl, array $vars = array()) {
    global $conf, $header, $token;
    extract($vars);                              // 变量注入模板作用域
    if (empty($_SESSION['token'])) $token = CSRF::generate();
    require THEME_DIR . $conf['theme'] . DS . 'header.tpl.php';
    require THEME_DIR . $conf['theme'] . DS . $tpl . '.tpl.php';
    require THEME_DIR . $conf['theme'] . DS . 'footer.tpl.php';
    exit;
}
```

调用如 `self::render('user_settings', array('user'=>$user, 'errors'=>$errors, ...))`。

**风格 B：直接 require 三件套**（`user::view()`、`home::index()` 等少数动作）

```php
// app/user.controller.php:53-56
require THEME_DIR . $conf['theme'] . DS . 'header.tpl.php';
require THEME_DIR . $conf['theme'] . DS . 'user_view.tpl.php';
require THEME_DIR . $conf['theme'] . DS . 'footer.tpl.php';
exit;
```

**主题机制**：`$conf['theme']` 决定用 `theme/bootstrap/` 还是 `theme/tawian/`，两套模板文件名约定一致。这相当于 Xiuno 的 view 目录，但没有 `_include()` 插件覆盖机制——FlooBB 目前无插件系统。

**模板文件清单**（theme/bootstrap/）：

| 模板 | 用途 |
|---|---|
| header.tpl.php / footer.tpl.php | 全局头尾（所有页面必经） |
| homepage.tpl.php | 首页 |
| forum_view.tpl.php / forum_add.tpl.php | 版块页 / 新建版块 |
| topic_view.tpl.php / topic_create.tpl.php | 主题详情 / 新主题 |
| _topic_actions.tpl.php | 主题操作局部片段（锁/置顶/移动/删除按钮） |
| post_edit.tpl.php | 编辑回帖 |
| user_view.tpl.php / user_settings.tpl.php | 用户资料 / 个人设置 |
| auth_login / auth_register / auth_recovery / auth_reset | 登录 / 注册 / 恢复码展示 / 重置密码 |

### 11. 输出 HTML 与收尾

- 模板内 `$header['title']`、`$token`（CSRF 隐藏域）、控制器传来的变量直接可用
- 所有站内链接一律 `Router::url('auth/login')` 生成（自动带 APP_BASE 前缀），禁止硬编码根路径
- 每个 action 末尾都 `exit`，确保不落入其他逻辑
- 响应离开时 `header_register_callback` 注入的 `Server-Timing` 头带出本次请求的 DB 操作数与总耗时（302/403 也带）

## 完整示例分析

### 示例 1：访问首页 `http://example.com/floobb/`

1. `index.php` → `init.php` 引导（见上）
2. `Router::segments()` → 空数组 → `$controller = 'home'`
3. `dispatch('home')` → action 缺省 `index` → `HomeController::index()`
4. `Forum::listAll()` 取版块列表、`Topic::listLatest()` 取最新主题
5. 渲染 `header.tpl.php` + `homepage.tpl.php` + `footer.tpl.php`

### 示例 2：查看主题 `http://example.com/floobb/topic/view/t1?page=2&sort=oldest`

1. `$seg = ['topic','view','t1']`
2. `dispatch('topic')` → `TopicController::view('t1')`
3. `Topic::get('t1')` 不存在 → 404 页；存在则 `Forum::get()`、`Post::listByTopic('t1')`
4. `Router::query('page')` / `Router::query('sort')` 读修饰符 → `Topic::sortBy()` / 分页
5. `Topic::incrViews('t1')` 浏览 +1
6. `self::render('topic_view', ...)` → 模板里 include `_topic_actions.tpl.php`（版主操作按钮）

### 示例 3：登录 POST `http://example.com/floobb/auth/login`

1. `$seg = ['auth','login']`，REQUEST_METHOD = POST
2. `dispatch('auth')` → POST 感知：`method_exists($obj, 'loginPost')` 成立 → 调 `AuthController::loginPost()`（而非 `login()`）
3. `Auth::csrfCheck()` 失败 → 403
4. `param('username')` / `param('password')` 取值（密码字段传 `FALSE` 禁 htmlspecialchars，防改坏原值）
5. 校验失败 → `self::render('auth_login', array('error'=>...))`；成功 → `Auth::login()` 写 session（可选 RememberMe 令牌）→ `self::redirect('')` 回首页

## 关键函数说明

### Router::segments() - 解析 URL 路径段

```php
// 返回有序段数组，如 ['forum','view','123']
// 来源优先级：PATH_INFO → $_GET['r'] → 空（首页）
// 同时把段并入 $_REQUEST，使 param(0)/param(1) 兼容 Xiuno 风格取参
```

### Router::dispatch($controllerName) - 分发

```php
// ['forum','view','123'] → ForumController::view('123')
// POST 且存在 {action}Post() → 优先调 {action}Post()
// 类/方法不存在 → return false（index.php 输出 404）
```

### param($key, $defval, $htmlspecialchars, $addslashes) - 取请求参数

```php
// 从 $_REQUEST（COOKIE+POST+GET+路径段）取值
// 默认 htmlspecialchars 编码；密码等敏感字段必须传 FALSE 防止改坏原值
// Router::query($key, $defval) 是它的 query-string 专用封装
```

### Router::url($path) - 生成站内 URL

```php
// url('auth/login') → /floobb/auth/login（自动带 APP_BASE，子文件夹部署友好）
```

### Auth::user() / Auth::csrfCheck() / Auth::resume()

```php
Auth::user()        // 当前登录用户数组，未登录返回 null
Auth::csrfCheck()   // 校验 POST 的 CSRF token（失败即 403）
Auth::resume()      // init.php 里调用：从 session/RememberMe 恢复登录态
```

### CSRF::generate() / $token

```php
// token 只在缺失时生成并存 $_SESSION['token']（CSRF::check 成功后 unset）
// 模板表单里输出 <input type="hidden" name="token" value="<?= $token ?>">
```

## 与 Xiuno BBS 4.0 的逐项对照

| 维度 | Xiuno BBS 4.0 | FlooBB |
|---|---|---|
| 入口 | index.php 单入口 | index.php 单入口（相同） |
| 引导 | conf.php + xiunophp + plugin.func.php + model.inc.php + index.inc.php | init.php 一个文件包办 |
| 路由 | `param(0)` + switch-case → include route/xxx.php | `Router::segments()` + 类方法分发 |
| 路由格式 | `thread-123.htm`（连字符 + .htm） | `/topic/view/t1`（斜杠三段式） |
| HTTP 方法 | route 文件里 `if($method == 'POST')` | 方法名后缀约定 `{action}Post()`，dispatch 自动感知 |
| 业务代码 | route/*.php 过程式 | app/*.controller.php 类方法 |
| Model | model/*.func.php 函数式（user_read 等） | model/*.php 静态类（User::get 等） |
| 数据库 | MySQL + 缓存（file/memcache/redis） | flatDB 文件存储，无缓存层 |
| 插件 | `_include()` 覆盖 + Hook | 无（Phase 0-3 未实现） |
| 视图 | view/htm/*.htm + slot 模板继承 | theme/{主题}/*.tpl.php + header/footer require |
| URL 生成 | url('thread-123') | Router::url('topic/view/t1') |
| 取参 | param(0) / param('email') | 同名 param() 保留 + Router::query() |
| 安全门禁 | 无（靠目录结构） | `defined('FLOO') or die` |

## 总结

FlooBB 的请求处理流程：

1. **单一入口**：index.php（与 Xiuno 相同）
2. **单文件引导**：init.php 完成常量/库/自动加载/会话/CSRF/登录恢复
3. **类控制器分发**：三位置契约 `/控制器/动作/参数`，POST 自动路由到 `{action}Post()`
4. **静态类 Model**：User/Topic/Post/Forum 四个仓储类直读 flatDB
5. **require 三件套渲染**：header + 页面模板 + footer，主题可切换，模板内统一转义

理解流程的捷径：**记住类名映射规则（UserController→app/user.controller.php，User→model/User.php），然后任何 URL 按 `/` 切三段对号入座即可。**
